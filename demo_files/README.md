# Demonstration evidence files

Generated by `make_demo_files.py`. Upload these through the running
application (not by copying into `uploads/`) so that each one gets a real
SHA-256 fingerprint, a signed initial custody entry and an audit record.

| File | Category to choose | Used for |
|---|---|---|
| `crime_scene_photo.jpg` | Image | EXIF extraction; the Intact verdict screenshot |
| `server_access.log` | Log File | A second exhibit so the custody log has variety |
| `transaction_records.csv` | Data / Other | A third exhibit |
| `incident_report.pdf` | Document | A fourth exhibit |
| `suspect_photo.png` | - | **Will be rejected.** Windows PE executable renamed `.png`; proves FR-14 |
| `usb_device_listing.txt` | Other | Reserved for the case created live during the oral exam |

`suspect_photo.png` is a real PE binary header, not an image. Its magic bytes
resolve to `application/x-dosexec`, which is in `DANGEROUS_MIME_TYPES`, so the
upload route refuses it before anything is written. It is inert - it contains
no executable payload beyond the header structure.
